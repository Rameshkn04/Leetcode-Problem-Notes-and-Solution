# 3534. Path Existence Queries in a Graph II

**Difficulty:** Hard  
**Topics:** Graph, Binary Lifting, Two Pointers, Sorting

---

# Problem

You are given:

- `n` nodes numbered from `0` to `n-1`
- An array `nums`
- An integer `maxDiff`

An undirected edge exists between node `i` and node `j` if

```
|nums[i] - nums[j]| <= maxDiff
```

For each query `[u, v]`, return the **minimum number of edges** required to travel from `u` to `v`.

If no path exists, return `-1`.

---

# Key Observation

At first glance, this looks like a graph problem.

However,

```
n = 100000
```

Building every edge is impossible.

In the worst case,

```
O(n²)
```

edges may exist.

We need another way.

---

# Observation 1

Sort all nodes according to their values.

Example

```
nums = [1,8,3,4,2]

Sorted

Value  Node

1      0
2      4
3      2
4      3
8      1
```

Notice something important.

Nodes that are close in value become adjacent after sorting.

---

# Observation 2

Suppose

```
maxDiff = 3
```

The gaps become

```
1 -> 2 = 1
2 -> 3 = 1
3 -> 4 = 1
4 -> 8 = 4
```

Since

```
4 > maxDiff
```

the graph splits into

```
Component 1

1
2
3
4

Component 2

8
```

If a gap between consecutive values is greater than `maxDiff`,
there is no possible path crossing that gap.

So simply scanning the sorted array gives every connected component.

---

# Observation 3

Suppose we are currently at value

```
2
```

and

```
maxDiff = 3
```

Then in one edge we may jump to

```
3
4
5
```

Among all these possibilities,
jumping to the **furthest reachable value** is always optimal.

Example

```
2 -> 3 -> 6

or

2 -> 5 -> 6
```

The second path is never worse.

Therefore, from every sorted position,
we only need to know

> **the furthest index reachable in one move.**

---

# Step 1 : Sort

Store

```
(value, originalIndex)
```

Example

```
nums = [5,3,1,9,10]

Sorted

1  node2
3  node1
5  node0
9  node3
10 node4
```

Also store

```
pos[node]
```

which tells where every original node appears in the sorted array.

---

# Step 2 : Find Connected Components

Traverse the sorted values.

Whenever

```
values[i] - values[i-1] > maxDiff
```

start a new component.

Example

```
Values

1 3 5 9 10

Gaps

2 2 4 1
```

Components become

```
Component 0

1 3 5

Component 1

9 10
```

Any query between different components immediately returns

```
-1
```

---

# Step 3 : Compute the Furthest Reachable Node

Use a sliding window.

Maintain

```
i = current position
j = furthest reachable position
```

Move `j` while

```
values[j+1] - values[i] <= maxDiff
```

Example

```
Values

1 2 3 4 8

maxDiff = 3
```

For every index

```
1 -> 4

next = index of 4

2 -> 4

next = index of 4

3 -> 4

next = index of 4

4 -> 4

next = itself

8 -> 8

next = itself
```

This entire process is

```
O(n)
```

because both pointers move only forward.

---

# Step 4 : Binary Lifting

Now every node has exactly one jump.

Example

```
0 -> 3
1 -> 3
2 -> 3
3 -> 3
4 -> 4
```

Instead of moving one jump at a time,
precompute powers of jumps.

```
up[0][i]
```

=

```
1 jump
```

```
up[1][i]
```

=

```
2 jumps
```

```
up[2][i]
```

=

```
4 jumps
```

```
up[3][i]
```

=

```
8 jumps
```

Formula

```
up[k][i] =
up[k-1][ up[k-1][i] ]
```

Exactly the same idea as Binary Lifting used in LCA.

Complexity

```
O(n log n)
```

---

# Step 5 : Answer Queries

Suppose we need

```
left -----> right
```

If

```
different components
```

answer

```
-1
```

Otherwise

Use Binary Lifting.

Starting from the largest power,

```
Can I jump 16 steps?

Can I jump 8 steps?

Can I jump 4 steps?

Can I jump 2 steps?

Can I jump 1 step?
```

Always take the largest jump that still stays before the destination.

Finally,

```
answer = jumps + 1
```

# Why Greedy Works?

Suppose

```
A can reach

B
C
D
```

in one edge.

Choosing

```
D
```

(the furthest one)

can never increase the answer because

- every node reachable from B is also reachable after D in fewer or equal jumps
- all edges are unweighted
- we always want maximum progress

Therefore jumping to the furthest reachable node is always optimal.

# Python Solution

```python
from typing import List

class Solution:
    def minQueries(
        self,
        n: int,
        nums: List[int],
        maxDiff: int,
        queries: List[List[int]]
    ) -> List[int]:

        arr = sorted((v, i) for i, v in enumerate(nums))

        values = [x[0] for x in arr]

        pos = [0] * n
        for i, (_, idx) in enumerate(arr):
            pos[idx] = i

        comp = [0] * n
        cid = 0

        for i in range(1, n):
            if values[i] - values[i - 1] > maxDiff:
                cid += 1
            comp[i] = cid

        nxt = [0] * n
        j = 0

        for i in range(n):
            while j + 1 < n and values[j + 1] - values[i] <= maxDiff:
                j += 1

            nxt[i] = j

            if j == i:
                j += 1
                if j >= n:
                    j = n - 1

        LOG = n.bit_length()

        up = [nxt[:]]

        for _ in range(1, LOG):
            prev = up[-1]
            cur = [0] * n
            for i in range(n):
                cur[i] = prev[prev[i]]
            up.append(cur)

        ans = []

        for u, v in queries:

            l = pos[u]
            r = pos[v]

            if l > r:
                l, r = r, l

            if comp[l] != comp[r]:
                ans.append(-1)
                continue

            if l == r:
                ans.append(0)
                continue

            cur = l
            steps = 0

            for k in range(LOG - 1, -1, -1):
                if up[k][cur] < r:
                    cur = up[k][cur]
                    steps += 1 << k

            ans.append(steps + 1)

        return ans
```

# Key Takeaways

- Don't build the graph explicitly.
- Sorting converts the graph into intervals.
- Connected components are determined by consecutive gaps.
- A sliding window finds the furthest reachable node in **O(n)**.
- Binary Lifting answers shortest-path queries in **O(log n)**.
- Final complexity is **O((n + q) log n)**, which easily handles `10^5` nodes and queries.
