# 3532. Path Existence Queries in a Graph I

**Difficulty:** Medium  
**Topics:** Graph, Sorting, Union Find (DSU)

---

# Problem

You are given:

- `n` nodes numbered from `0` to `n-1`
- An integer array `nums`
- An integer `maxDiff`

An undirected edge exists between nodes `i` and `j` if

```
|nums[i] - nums[j]| <= maxDiff
```

For each query `[u, v]`, determine whether a path exists between node `u` and node `v`.

Return a boolean array where

- `true` → a path exists
- `false` → no path exists

---

# Key Observation

Building the entire graph is impossible.

```
n = 100000
```

In the worst case,

```
O(n²)
```

edges can exist.

Instead of building every edge, we only need to determine which nodes belong to the same connected component.

---

# Observation 1

Sort the nodes according to their values.

Example

```
nums = [5,3,1,9,10]

Sorted

Value   Node

1       2
3       1
5       0
9       3
10      4
```

Now nodes with similar values become neighbors.

---

# Observation 2

Suppose

```
maxDiff = 2
```

The gaps are

```
1 → 3 = 2
3 → 5 = 2
5 → 9 = 4
9 → 10 = 1
```

Whenever

```
gap > maxDiff
```

the graph becomes disconnected.

So the connected components are

```
Component 1

1
3
5

Component 2

9
10
```

---

# Observation 3

If two consecutive values satisfy

```
difference <= maxDiff
```

then they are directly connected.

Using Union Find (Disjoint Set Union), we simply union every adjacent pair in the sorted array.

Example

```
Sorted values

1 3 5 9 10

Union

1 ↔ 3

3 ↔ 5

9 ↔ 10
```

No need to check every pair.

---

# Algorithm

## Step 1

Sort

```
(value, originalIndex)
```

---

## Step 2

Traverse consecutive pairs.

If

```
values[i] - values[i-1] <= maxDiff
```

perform

```
union(node1, node2)
```

---

## Step 3

For every query

```
[u, v]
```

check

```
find(u) == find(v)
```

If yes

```
True
```

otherwise

```
False
```

# Why Does This Work?

Suppose

```
a < b < c
```

If

```
b-a <= maxDiff

c-b <= maxDiff
```

then

```
a → b → c
```

forms a valid path.

Therefore, connecting only consecutive sorted values is sufficient to connect the entire component.

There is no need to compare every pair of nodes.

# Complexity Analysis

Sorting

```
O(n log n)
```

Union Operations

```
O(n α(n))
```

Queries

```
O(q α(n))
```

where

```
α(n)
```

is the inverse Ackermann function (almost constant).

Overall

```
O(n log n + q)
```

Space

```
O(n)
```

# Python Solution

```python
from typing import List

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [1] * n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x, y):
        px = self.find(x)
        py = self.find(y)

        if px == py:
            return

        if self.rank[px] < self.rank[py]:
            px, py = py, px

        self.parent[py] = px

        if self.rank[px] == self.rank[py]:
            self.rank[px] += 1


class Solution:
    def pathExistenceQueries(self, n: int, nums: List[int], maxDiff: int, queries: List[List[int]]) -> List[bool]:

        arr = sorted((nums[i], i) for i in range(n))

        dsu = DSU(n)

        for i in range(1, n):
            if arr[i][0] - arr[i - 1][0] <= maxDiff:
                dsu.union(arr[i][1], arr[i - 1][1])

        ans = []

        for u, v in queries:
            ans.append(dsu.find(u) == dsu.find(v))

        return ans
```

# Key Takeaways

- Never build the graph explicitly.
- Sort nodes by value.
- Connect only adjacent sorted nodes.
- Use Union Find (DSU) to build connected components.
- Each query becomes a simple connectivity check.
- Overall complexity is

```
O(n log n + q)
```

which easily handles `10⁵` nodes and queries.
