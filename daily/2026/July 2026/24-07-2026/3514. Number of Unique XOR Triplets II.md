# 3514. Number of Unique XOR Triplets II

**Difficulty:** Medium

---

# Intuition

The problem asks us to find the number of **distinct XOR values** obtained by selecting three elements from the array such that

```
i <= j <= k
```

and computing

```
nums[i] XOR nums[j] XOR nums[k]
```

Notice that:

- Indices may repeat (`i == j`, `j == k`, etc.).
- Therefore, if a value exists in the array, we may use it multiple times.
- We only care about **unique XOR results**, not how many ways they can be formed.

A brute-force solution checks every triplet.

```
O(n³)
```

With

```
n ≤ 1500
```

this becomes

```
1500³ ≈ 3.3 billion operations
```

which is far too slow.

---

# Key Observation

Each element satisfies

```
1 <= nums[i] <= 1500
```

Since

```
1500 < 2048 = 2¹¹
```

every value fits inside **11 bits**.

Therefore every XOR result also lies in the range

```
0 ... 2047
```

So instead of thinking about **1500 indices**, we think about only

```
2048 possible values.
```

---

# Mathematical Idea

Create a frequency array.

```
f[x] = 1  if value x exists
f[x] = 0  otherwise
```

Example

```
nums = [6,7,8,9]
```

Only

```
f[6] = 1
f[7] = 1
f[8] = 1
f[9] = 1
```

All others are zero.

Now we need every possible value

```
a XOR b XOR c
```

where

```
f[a] = f[b] = f[c] = 1
```

This is exactly a **3-fold XOR convolution**.

---

# XOR Convolution

Normal convolution works with

```
i + j
```

XOR convolution works with

```
i XOR j
```

For two arrays

```
A
B
```

the XOR convolution is

```
C[x] = Σ A[i] × B[j]
       where i XOR j = x
```

Computing this directly takes

```
O(N²)
```

where

```
N = 2048
```

Instead we use the

> **Fast Walsh-Hadamard Transform (FWHT)**

which computes XOR convolution in

```
O(N log N)
```

---

# Fast Walsh-Hadamard Transform (FWHT)

FWHT is the XOR equivalent of FFT.

Instead of multiplying polynomials using addition,

FWHT performs multiplication using XOR.

The transform repeatedly applies

```
(x, y)

↓

(x + y,
 x - y)
```

over blocks of increasing size.

---

## Example

Suppose

```
[1,2,3,4]
```

### Step 1

Pair adjacent elements.

```
(1,2)

↓

(3,-1)

(3,4)

↓

(7,-1)

Result

[3,-1,7,-1]
```

---

### Step 2

Combine larger blocks.

```
3 and 7

↓

10,-4

-1 and -1

↓

-2,0

Final

[10,-2,-4,0]
```

This is the transformed array.

---

# Why Cube?

After FWHT,

XOR convolution becomes simple multiplication.

The important identity is

```
FWHT(A XOR-convolution B)

=

FWHT(A) × FWHT(B)
```

(element-wise multiplication)

We need

```
A XOR B XOR C
```

which is

```
f * f * f
```

Instead of three convolutions,

after transformation we simply compute

```
FWHT(f)^3
```

Therefore

```python
for i in range(N):
    f[i] = f[i] ** 3
```

Finally,

apply inverse FWHT.

The resulting array tells us exactly which XOR values are achievable.

Every non-zero entry represents one distinct XOR value.

---

# Algorithm

1. Create an array of size **2048**.
2. Mark every value present.
3. Apply FWHT.
4. Cube every transformed value.
5. Apply inverse FWHT.
6. Count every non-zero entry.

---

# Correctness Proof

We prove that the algorithm returns exactly the number of unique XOR triplets.

### Lemma 1

The frequency array correctly represents every available value.

Since repeated indices are allowed,

every existing value may be selected any number of times.

Thus the problem depends only on whether a value exists.

---

### Lemma 2

FWHT converts XOR convolution into element-wise multiplication.

This is a standard property of the Walsh-Hadamard Transform.

Therefore

```
FWHT(f XOR f XOR f)

=

FWHT(f)³
```

---

### Lemma 3

Applying inverse FWHT reconstructs the XOR convolution.

Thus every achievable XOR value receives a positive count.

Impossible XOR values remain zero.

---

### Theorem

The algorithm counts exactly every achievable XOR triplet value once.

Hence the returned answer is correct.

---

# Complexity Analysis

Let

```
N = 2048
```

FWHT

```
O(N log N)
```

Transform

```
2048 × log₂2048

=

2048 × 11

≈ 22,500 operations
```

Memory

```
O(2048)
```

This easily satisfies the constraints.

# Python Solution

```python
from typing import List

class Solution:
    def uniqueXorTriplets(self, nums: List[int]) -> int:
        N = 2048

        # Frequency array
        f = [0] * N
        for x in nums:
            f[x] = 1

        # Fast Walsh-Hadamard Transform
        def fwht(a, inverse=False):
            n = len(a)
            h = 1

            while h < n:
                for i in range(0, n, h * 2):
                    for j in range(i, i + h):
                        x = a[j]
                        y = a[j + h]

                        a[j] = x + y
                        a[j + h] = x - y

                h <<= 1

            if inverse:
                for i in range(n):
                    a[i] //= n

        # Forward transform
        fwht(f)

        # Three-fold XOR convolution
        for i in range(N):
            f[i] = f[i] ** 3

        # Inverse transform
        fwht(f, True)

        # Count distinct XOR values
        return sum(x != 0 for x in f)
```

# Takeaways

- Since indices may repeat, only **distinct values** matter.
- XOR results are limited to **2048** possible values.
- XOR convolution can be solved efficiently using **Fast Walsh-Hadamard Transform (FWHT)**.
- FWHT converts XOR convolution into simple element-wise multiplication.
- Cubing the transformed frequencies performs the required **three-fold XOR convolution**.
- Overall complexity is **O(2048 log 2048)**, which is extremely fast.
